# 需求补充 V1.1

2026-10-13。保留 `requirements-v1.0.md` 原稿；本文件说明建仓落实时的补充，不改写原业务目标。

1. 仓库使用已创建的 `iurp/fdex-tender-agent`，教师维护一个共用基座。学员从当前主干做增量任务，是否采用 workshop 私人版本由价值决定。
2. V0.1 首个可运行参考实现只支持 DEMO 人员资质局部章节。18模块进入路线图；每个 AC 的状态在实现范围记录，不把模块函数存在称为完整验收。
3. 公共信封冻结为 `bid-training.workflow.v1`，顶层字段与状态按原稿实现。原文定位、项目、标包、模式和输入哈希必须保留。
4. 初始原文适配为带稳定条款标签的 Markdown；材料字段从声明侧文件读取，检查图片文件但不宣称 OCR。PDF、图像字段提取、任意模板需要单独任务和验证。
5. 模拟确认由输入文件提供。变更相关要求或所选材料时确认摘要不匹配，状态 STALE。本地 DEMO 放行要求显式提供审核人，绑定实际 DOCX 哈希和局部范围。
6. 学员工程任务的主要负责人唯一；协作者另行登记。认领由串行协调工作流确认；高级任务先登记计划。求助、已提交PR和待审查暂停无进展回收。
7. 所有PR绑定已发布任务，CI验证公开合成输入。审查必须针对当前提交；普通PR经维护者批准后自动合并。作者自审不能算独立批准。
8. GitHub事件立即进入任务/PR队列；模型审查的运行入口与密钥接入单独记录。不存在的模型执行服务不能由“已设置标签”冒充。
9. 基座代码合并、人员选用、商务承诺、文档放行和真实递交分别验收。工程自动化不产生后四者的业务授权。
10. 新学员从 README 自助安装与任务认领。教学起点将固定为版本标签；持续项目使用最新主干。当前许可尚未指定为开源许可证，公开阅读不自动赋予商业再分发许可。
